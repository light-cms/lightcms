大多数内容平台都将您的写入数据库，在他们的服务器上渲染，并要求您继续访问它。当平台关闭、提升价格或更改其条款时，您的内容会与之相伴。

[LightCMS](https://www.lightcms.me) 采取不同的位置：您的内容作为普通Markdown文件生活在您自己的 Git 仓库中。 [LightCMS](https://www.lightcms.me) 永远不会触碰你的阅读器 — 它只是在你写入时运行。

## 托管CMS平台的核心问题

当您在传统托管CMS上发布时，您正在其他人的数据库中租用空间。这听起来很好，直到出了错。

平台杀死您的计划层级。他们增加了一个新的存储限制。他们已经获得。导入工具断开。多年内容突然迁移是你没有预算的一个下午的工作。

即使没有任何错误，锁定也是静静静的，而是真实的。您的内容被困在 API 后面的专利格式。您不能在自己的文章中运行一个 `grep`。您不能将草稿与前一版本相差悬殊。您不能解决帖子中的合并冲突。

使用 [LightCMS](https://www.lightcms.me)，内容已承诺作为Markdown文件支持您的repo。就是这样。你的发布管道只是一个静态站点生成器 — Astro、Hugo、Jekyl、Eleventy、Zola，不管你已经在使用的任何东西。 [LightCMS](https://www.lightcms.me) 是顶部的编辑层。随时交换，您的内容未触摸。

## 基于 Git 的发布实际意味着什么

每次保存都是提交的。每个编辑都是可审计的，并控制版本。每个帖子都有完整的历史记录，返回到第一稿。

协作对代码的作用是一样的：草稿分支、请求审核、提交消息作为更新日志。如果您对Git已经感到舒适，这是您已经拥有的在你的堆栈中所有其他东西的智力模型。

翻转是读者从未碰到过 [LightCMS](https://www.lightcms.me) 内容已承诺到您的仓库，构建管道运行 (Cloudflare页面、Netlify) Vercel, GitHub Pages)，输出来自一个 CDN 边缘节点的静态HTML服务。没有应用程序服务器在您的阅读器和内容之间。

这关系到性能-缓存的静态文件加载快速。它还与费用有关。大多数东道主拥有免费等级，涵盖高流量个人网站或无月度账单的小型出版物。

## 编辑器不会让你想到其中任何一个

Git机械师在后台运行。来自编辑器的体验只是写作。

基于 TipTapp 的编辑器写清理Markdown。如果你喜欢语音，你可以使用任何Whisper兼容的 API 或 Wit.ai 。内置的 AI 拷贝可与任何OpenAI兼容的端点兼容，可以改进草稿，修理句子，或接下来的地方。

当您点击发布时，LightCMS会将文件提交到您配置的路径，您的部署管道将接管。如果你在 Cloudflare 页面上，帖子就在一分钟内存活。

## LightCMS 不是

它不是一个托管博客平台。您和您的阅读者之间没有LightCMS管理的基础设施。 LightCMS是你作为写作者运行的软件，它写入你拥有的仓库中。

## 可持续性角度

静态站点每次页面视图所产生的CO2要比服务器呈现的当量少得多。没有总是开启的数据库，没有每个请求的渲染，也没有服务器来保持警戒。点击CDN缓存的页面视图大多只是一个网络跳跃。

[研究将一个典型的静态缓存页面放在大约0个页面。 每次访问的](https://www.websitecarbon.com/) 2克CO2 — — 对于一个重量的服务器渲染页面而言，一个克或更多。这种差距在数百万页浏览量中更加严重。

它不是选择静态建筑的主要原因，而是如果基础设施的环境成本对你来说是重要的，那将是一种真正的好处。

## 谁是

LightCMS适合于以下情况：

- 您是在静态站点生成器上运行博客的开发者，希望自己或合作者有体面的编辑器
- 您希望您的写入超出任何单个平台
- 您想要为内容交付提供零托管成本
- 你想要你的内容格式为 AI 编码代理、搜索工具和自定义脚本都可以本地读取的格式

如果你需要实时功能、复杂的关系内容结构或一个完全管理的平台，别人处理基础设施，这不是一件好事。
