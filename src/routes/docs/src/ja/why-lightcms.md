ほとんどのコンテンツプラットフォームは、書き込みをデータベースに格納し、それをサーバーにレンダリングし、アクセスを維持するために課金します。プラットフォームがシャットダウンしたり、価格を上げたり、用語を変更したりすると、コンテンツはそれに伴います。

[LightCMS](https://www.lightcms.me) は異なる位置になります。つまり、コンテンツはプレーンMarkdown ファイルとして、あなた自身のGitリポジトリに存在します。 [LightCMS](https://www.lightcms.me) はあなたの読者に触れることはありません — それはあなたが書いている間のみ実行されます。

## Hosted CMS Platformsのコア問題

従来のホストされているCMSで公開すると、他の誰かのデータベースでスペースを借りることになります。何かがうまくいかなくなるまで、それはいいように聞こえる。

プラットフォームはプラン階層を倒します。これらは新しいストレージ制限を追加します。彼らは獲得されます。インポートツールが中断します。突然、コンテンツの長年の移行は、あなたが予算を費やしていなかった仕事の午後です。

何も間違っていなくても、ロックインは静かですが、本物です。コンテンツは、API の背後に独自の形式で閉じ込められています。自分の記事で `grep` を実行することはできません。以前のバージョンに対して下書きを変更することはできません。ポスト内のマージ競合を解決できません。

[LightCMS](https://www.lightcms.me)を使用すると、コンテンツは Markdown ファイルとしてリポジトリにコミットされます。以上ですパブリッシングパイプラインは、アストロ、ヒューゴ、Jekyll、Eleventy、Zola、すでに使用しているものは何でも、単なる静的サイトジェネレータです。 [LightCMS](https://www.lightcms.me) が上部のエディターレイヤーです。いつでも交換すれば、コンテンツはそのままになります。

## Git ベースのパブリッシングが実際に意味するもの

すべてのセーブはコミットです。すべての編集は監査可能でバージョン管理されています。すべての投稿には、最初のドラフトに戻って完全な履歴があります。

コラボレーションは、コードの場合と同じように機能します。下書きの場合はブランチ、レビューの要求のプル、変更履歴としてメッセージをコミットします。あなたがすでにGitに慣れているならば、これはあなたのスタック内の他のすべてのためにすでに持っている精神的なモデルです。

逆に、読者は決して [LightCMS](https://www.lightcms.me) をヒットしないということです。コンテンツはリポジトリにコミットされ、ビルドパイプラインが実行されます（Cloudflare Pages、Netlify） Vercel, GitHub Pages)と出力は、CDNエッジノードから動作する静的HTMLです。リーダーとコンテンツの間にアプリケーション・サーバーがありません。

これはパフォーマンスにとって重要です — キャッシュされた静的ファイルは高速にロードされます。それはまた費用のために重要である。これらのホストのほとんどは、毎月の請求書なしで高トラフィックの個人サイトや小規模な出版物をカバーする無料の層を持っています。

## エディターではこれについて考えさせません

Git の仕組みは、バックグラウンドで実行されます。エディタからは、経験はちょうど書いている。

TipTapベースのエディタはクリーンマークダウンを書き込みます。 Whisper互換のAPIやWit.aiを使って音声を指定することができます。組み込みの AI 副操縦士は、任意の OpenAI 互換のエンドポイントで動作し、ドラフトを絞り込んだり、文章を修正したり、中断した場所を拾ったりすることができます。

パブリッシュにヒットすると、LightCMS は設定したパスにファイルをコミットし、デプロイパイプラインが引き継がれます。 Cloudflare Pagesをご利用の場合、投稿は約1分以内に配信されます。

## LightCMSとは何か

これはホスト型ブログプラットフォームではありません。あなたと読者の間にLightCMS管理されたインフラストラクチャはありません。 LightCMS はライターとして実行されるソフトウェアで、所有しているリポジトリに書き込みます。

## サステナビリティ角度

静的サイトでは、ページビューあたりのCO2排出量がサーバレンダリングと同等のものよりも大幅に少なくなります。常時オンのデータベースもリクエスト毎のレンダリングもなく、暖かく保つサーバーもありません。 CDN キャッシュに当たるページビューは、ほとんどがネットワークホップです。

[Research puts a typical static, cached page at around 0.002 grams of CO2 per visit](https://www.websitecarbon.com/) — versus a gram or more for a heavy, server-rendered page. このギャップは何百万ページものページビューに広がっています

静的なアーキテクチャを選択する主な理由ではありませんが、インフラの環境コストが重要な場合、それは本当の利益です。

## それは誰のためのもの

LightCMS は以下の場合に適合します:

- あなたは静的サイトジェネレータでブログを運営している開発者で、あなた自身や共同編集者のためにきちんとしたエディタが必要です。
- どのプラットフォームよりも長く書くことを望んでいます
- コンテンツ配信に必要なホスティングコストがゼロです
- AIコーディングエージェント、検索ツール、およびカスタムスクリプトがすべてネイティブに読み取れる形式でコンテンツを必要とします

リアルタイムの機能、複雑なリレーショナルコンテンツ構造、または他の人がインフラストラクチャを処理する完全に管理されたプラットフォームが必要な場合には適合しません。
